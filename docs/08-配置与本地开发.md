# 配置与本地开发

本文档统一说明配置分层、本地启动、测试和常见开发入口。业务字段的详细数据结构以 [06-数据模型.md](06-数据模型.md) 和 [07-接口契约.md](07-接口契约.md) 为准。

## 1. 配置分层

### 1.1 环境变量

只保存启动所需和部署环境相关配置：

```text
数据库连接
Redis 连接
API / Worker 启动参数
日志输出方式
本地缓存根目录
开发模式开关
```

业务运行配置优先进入 PostgreSQL，不继续扩张 `.env`。`.env`、Token、Cookie、SMB 密码和平台密钥不得提交。

### 1.2 数据库配置

数据库保存：

- SMB 连接、媒体库、远程媒体库和同步绑定；
- Transfer 与扫描策略；
- 插件仓库、锁定 commit、插件启停和配置；
- 媒体发现游标及必要业务状态。

Redis 丢失不能导致上述事实丢失。

### 1.3 敏感字段

- API 返回敏感配置时统一显示 `***`。
- 更新请求中的 `***` 表示保留原值。
- 插件错误、日志和诊断需要替换已知敏感值并限制长度。
- 凭据只提供给明确声明所需 Core 能力的插件实例。

## 2. 运行环境

建议环境：

```text
Python 3.12+
Node.js 20+
PostgreSQL
Redis
```

仓库主要目录：

```text
sundarr/app       后端 API、服务、模型、插件宿主和 Worker
web               React + Vite Web Console
tests             Core 自动化测试
alembic           数据库迁移
docs              当前规范
examples          离线示例和开发模板
```

## 3. 启动方式

完整本地启动优先使用项目 CLI；实际参数以 `sundarr --help` 为准：

```powershell
sundarr start
sundarr status
sundarr stop
```

PID 文件必须指向真实 API、Web 和 Worker 进程，不能指向日志包装进程。

Docker Compose 用于 PostgreSQL、Redis 和可选完整部署。容器日志默认写 stdout/stderr，由 Docker logging driver 控制轮转；本地 CLI 可写受控大小的文件日志。

## 4. 单独开发

后端常用入口：

```powershell
python -m pytest
alembic upgrade head
```

前端常用入口：

```powershell
Set-Location web
npm install
npm run dev
npm run build
```

不要把本地端口、路径和凭据写死到代码或提交文件中。

## 5. 插件仓库

Core 启动时从数据库 enabled 状态和本地缓存的锁定 `current_commit` 恢复所需插件；不会自动 fetch 或执行远程最新代码。未配置 Provider 时：

- `/search` 返回空结果表示没有已启用 SOURCE；
- `/app/discover` 显示“尚未启用目录 Provider”；
- Core `/health` 仍应正常。

官方插件开发在相邻独立仓库进行：

```text
C:\Users\SUNDAY\project\sundarr-sources
C:\Users\SUNDAY\project\sundarr-plugin
```

仓库位置是当前开发机事实，不属于部署合同。插件开发规则见 [16-插件仓库与开发.md](16-插件仓库与开发.md)。

## 6. 测试数据

- 默认测试使用 LocalWriter、离线 fixture 和可重复的 Provider 替身。
- 面向用户的目录页面不提供 Mock 数据链。
- 真实插件测试必须通过显式标记或独立命令运行，并从环境读取凭据。
- 真实 SMB 测试只能写入用户明确授权的目录，测试前后核对目标路径。

## 7. 数据库迁移

- 模型变化必须配套 Alembic 迁移。
- 新迁移的 `down_revision` 必须指向当前唯一 head。
- 至少验证全新数据库升级；高风险变更还需验证从上一已发布 revision 升级。
- 不通过删除本地数据库来掩盖迁移问题。

## 8. Git 与文本

- 默认在 `master` 提交，提交信息和面向用户文本使用简体中文。
- 不提交 `.env`、凭据、私有链接、测试账号或真实 Cookie。
- 不回滚或覆盖用户未授权修改。
- 完成可验证交付单元后提交；push 仍需用户明确授权。

## 9. 最小验收

```text
后端：pytest + 受影响 API/CLI/Worker 冒烟
前端：npm run build + 受影响页面冒烟
配置/Docker：配置校验 + health/连接冒烟
数据库：迁移升级验证
文档：索引、引用、状态和文件名一致性检查
```
