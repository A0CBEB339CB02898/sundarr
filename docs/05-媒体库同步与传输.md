# 媒体库同步与传输

本文档统一定义 SMB 存储写入、远程媒体库扫描、同步绑定和传输任务状态机。系统核心链路是“远程媒体库同步到本地媒体库”，不再使用“网盘导入”或“下载到本地”作为当前模块名。

状态：模型、API、Web Console、扫描、任务创建和 Worker 自动化路径已实现；真实来源 SMB 到目标 SMB 的完整流程仍是 MVP 发布前手动验收门。

## 1. 对象关系

```text
SmbConnection
  ├─ RemoteMediaLibrary（来源目录）
  └─ MediaLibrary（目标 NAS 媒体目录）

SyncBinding
  = RemoteMediaLibrary -> MediaLibrary
```

连接集中保存主机、共享目录和凭据。媒体库与同步绑定只引用连接和子目录，不重复保存 SMB 密码。

本地媒体库类型为 `movie`、`series` 或 `unclassified`。不能可靠分类时必须进入 `unclassified`，不得猜测目标目录。

## 2. 扫描与任务创建

Worker 或显式 API 扫描启用的同步绑定：

1. 列出来源目录并拒绝越过绑定根路径。
2. 忽略临时文件、未稳定文件和已处理记录。
3. 通过连续扫描大小与修改时间判断文件稳定。
4. 写入 `SyncSeenFile`，保证重复扫描幂等。
5. 为稳定文件创建 `TransferTask` / `TransferFile`。
6. 任务持久化来源、目标、绑定、配置快照和清理策略。

扫描发现不等于完成传输。绑定被禁用或配置失效时不得继续创建新任务。

## 3. StorageWriter 合同

Core 使用统一写入接口。`LocalWriter` 用于离线测试；`SmbWriter` 使用应用内 SMB 客户端，不依赖系统 mount。

主要能力：

```text
exists / size / mkdirs
open_read / open_append
rename / remove / remove_empty_dir
list_dir / connection_test
```

路径规则：

- 所有相对路径必须解析到配置的媒体库根目录以内。
- 拒绝绝对系统路径、`..` 穿越和 UNC 注入。
- 默认不覆盖已存在的正式目标文件。
- 临时目标统一使用 `<目标文件>.downloading`。

## 4. 写入与续传

```text
构造安全目标路径
  -> 创建父目录
  -> 检查 .downloading 大小
  -> 从可信 offset 继续读取来源
  -> 追加写入临时文件
  -> 校验大小或校验和
  -> 原子 rename 为正式文件
```

- 来源支持 offset 时可以续传；否则从头重写临时文件。
- 临时文件大于来源时视为无效，不能静默拼接。
- 只有临时大小与来源一致、校验通过且正式目标不存在时才允许重命名。
- 目标已存在时默认失败，除非未来另行定义覆盖策略。

## 5. 状态机

任务主要状态：

```text
pending -> running -> completed
                └-> failed
pending/running -> cancelled
failed -> pending（显式重试）
```

文件执行阶段记录在任务/文件进度中：准备、复制、校验、重命名和清理。持久状态必须足以在 Worker 重启后判断下一步，不能依赖内存回调。

### 5.1 认领与并发

- Worker 使用数据库锁或等价原子操作认领 `pending` 任务。
- 同一任务不能被两个 Worker 同时执行。
- 心跳和更新时间用于识别失联任务；启动恢复只能恢复满足规则的任务。

### 5.2 失败

失败至少记录：

```text
error_code
error_message（脱敏）
retryable
failed_at
```

可重试错误进入 `failed`，由用户或策略显式重试回 `pending`。不可重试错误不得自动循环。

### 5.3 取消

取消是持久请求。Worker 在安全检查点停止读取和写入，任务进入 `cancelled`；默认保留可续传的 `.downloading`，除非用户明确执行安全清理。

### 5.4 SMB 配置变化

修改 SMB 配置时：

```text
清除旧连接缓存
中断使用旧快照的运行中任务
task.status = failed
error_code = STORAGE_CONFIG_CHANGED
retryable = true
保留 .downloading 和来源暂存
```

新任务和显式重试使用最新配置。

### 5.5 Worker 恢复

- 启动时检查遗留 `running` 任务、临时文件和目标文件。
- 正式目标已存在且校验符合时可以收口完成状态。
- 只有可信临时大小才能续传。
- 无法证明安全时进入明确失败，不得猜测完成或删除文件。

## 6. 来源清理

成功后可按绑定策略删除来源文件和空目录，但必须满足：

- 目标正式文件已完成校验和重命名；
- 数据库任务已记录完成事实；
- 删除路径仍位于授权来源根目录；
- 不删除非空目录、未知文件或其他绑定的内容。

失败、取消、配置变化和未完成校验时不得删除来源。

## 7. API 范围

具体字段以 [07-接口契约.md](07-接口契约.md) 为准，能力分为：

```text
/storage/smb-connections  连接 CRUD、测试和浏览
/media-libraries          本地媒体库管理
/remote-media-libraries   远程媒体库管理
/sync/bindings            同步绑定管理和测试
/sync/scan                扫描
/sync/discovered          扫描发现结果
/sync/tasks/create        创建同步任务
/transfers                查询、取消、重试和日志
```

## 8. 插件化边界

当前 `SmbWriter`、扫描和传输状态机是 Core 内置能力，不是外部插件。未来如引入 `TRANSFER_DRIVER`，应先让内置 SMB 实现同一合同，再评估 HTTP、网盘或下载客户端；驱动选择必须在任务创建前持久化，插件运行中不得任意改写流向。

## 9. 验收标准

- LocalWriter 与 SmbWriter 合同均有自动化测试，默认测试不连接真实 NAS。
- 路径穿越、覆盖保护、续传、校验、重命名和配置变化均有测试。
- 扫描重复执行不重复创建任务。
- 失败、取消、重试和 Worker 重启后的状态可追踪且可恢复。
- 来源清理只在成功后发生，并受授权根目录保护。
- 发布前在明确授权目录完成真实 SMB 全链路和清理验收。
