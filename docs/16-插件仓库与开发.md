# 插件仓库与开发

本文档定义官方外部仓库边界，以及外部 Python 插件的开发、测试和发布规则。生命周期语义见 [14-插件系统.md](14-插件系统.md)，Manifest 字段见 [15-插件清单.md](15-插件清单.md)。

更新时间：2026-08-31。

## 1. 仓库边界

### 1.1 Sundarr Core

Core 保留：

```text
公共合同和 SDK 类型
Manifest / Loader / Activation / Registry
仓库配置、锁定、更新、回滚和诊断
业务编排、持久状态和 Web Console
离线测试替身、fixture 和 conformance runner
```

平台专用 HTTP、解析、配置 schema、实时集成测试和平台 fixture 不得写回 Core。

### 1.2 官方 SOURCE 仓库

```text
仓库：https://github.com/A0CBEB339CB02898/sundarr-sources.git
职责：SeedHub 等具体资源链接搜索 SOURCE
边界：敏感资源搜索独立发布、锁定和回滚
```

2026-08-31 历史基线只证明 SeedHub v1 列表搜索可用，真实详情仍停留在站内 `/link_start/` 跳转。因此本次迁移同时完成了 Manifest v2、跳转解析和 Core 真实回归，而不是只更换清单格式；当前状态见本文件第 5、8 节。

### 1.3 其他官方插件仓库

```text
仓库：https://github.com/A0CBEB339CB02898/sundarr-plugin.git
职责：CATALOG_PROVIDER、WATCHLIST_PROVIDER 和未来其他非 SOURCE 官方插件
首个交付：TMDb CATALOG_PROVIDER
```

两个官方仓库独立锁定 commit。`sundarr-plugin` 是官方集合仓库，不是插件市场；其中每个 `plugin_id` 仍独立配置、启停、健康检查和报错。

第三方仓库可以使用同一 v2 合同接入，Core 不假设系统只有一个仓库。

## 2. 最小仓库结构

```text
repository/
  sundarr_plugin.toml
  src/
    package_name/
      __init__.py
      plugin.py
  tests/
    fixtures/
    test_contract.py
    test_live_integration.py
  pyproject.toml
  README.md
  AGENTS.md
```

一个仓库可以声明多个插件，例如 `douban-catalog` 与 `douban-watchlist`，但每个声明只有一个主 `PluginType`。

## 3. 入口与公共合同

所有新插件使用 Manifest v2，入口接收 `PluginContext` 并返回主类型合同实例：

```python
def activate(context):
    client = create_client(
        context.require("core.http.v1"),
        context.plugin_config,
    )
    context.register_cleanup(client.close)
    return create_provider(client)
```

类型返回值：

- `SOURCE`：`SourceModel`，查询返回 `RawSearchItem`。
- `CATALOG_PROVIDER`：`CatalogProvider`，返回 `CatalogItem` / `CatalogPage`。
- `WATCHLIST_PROVIDER`：`WatchlistProvider`，返回 `WatchlistItem` / `WatchlistPage`。

TMDb 身份命名空间必须区分 `tmdb.movie` 和 `tmdb.tv`。目录 Provider 通过 `CatalogCapabilities.identity_namespaces` 声明可稳定回查的命名空间。跨 Provider 精确归并依赖相同外部 ID；缺失外部 ID 时不得仅靠标题静默合并。

## 4. 插件职责

插件负责：

- 请求目标平台并处理平台分页、限流和错误；
- 把真实响应映射为公共合同对象；
- 提供配置 schema、离线 fixture、健康检查和实时集成测试；
- 对自己创建的连接、订阅和回调登记 cleanup。

Core 负责：

- 媒体身份、最小快照、缓存降级、想看游标和调度；
- SOURCE 后处理、收藏标记和收藏持久化；
- 数据库、任务、SMB、Worker 和 Web Console。

插件禁止直接访问 ORM Session、SMB 凭据或任务状态机写接口，也不得在 import 阶段联网、启动线程或创建长期副作用。

## 5. 测试要求

默认 `pytest`：

- 使用离线 fixture，不访问实时平台；
- 覆盖正常、空结果、字段缺失、响应变化、超时和配置错误；
- 校验 `plugin_id`、返回对象、能力声明和身份命名空间；
- 不在导入阶段读取凭据或发送请求。

显式实时集成测试：

- 从当前测试进程的环境变量读取密钥或 Cookie，绝不写入仓库或修改 Sundarr 数据库；该方式只用于隔离测试，不是正式运行配置入口；
- 每次新增或修改真实插件都必须运行；
- 使用 Core 公共 conformance runner 回归声明能力；
- 同时回归受影响的 Core API 和 Web Console 主路径。

首个 TMDb 插件至少覆盖搜索、热门电影、热门剧集、分类/筛选、详情、海报 URL、分页和错误降级。

当前 `sundarr-plugin` 已完成上述实现、离线 fixture、Core conformance runner 和 Core `/discover` API 跨仓库集成回归。2026-08-31 已使用有效凭据完成实时测试，并在 `/app/discover` 验证真实海报墙、URL 查询状态和详情页；Provider 禁用时的最小快照降级、密文配置与脱敏也已通过，Plugin API v2 已冻结。

豆瓣目录以 `Marvae/douban-cli`（MIT）的公开接口覆盖和解析方式作为参考，但必须在 `sundarr-plugin` 中使用 Python 独立实现，不复制其 Node.js 运行环境，也不在插件启动时下载或导入参考仓库。参考用途限于搜索、热门、分类、详情端点与字段语义核对；提交前仍要审查许可证边界、fixture 和署名文案。`thomashirtz/douban-crawler` 是批量抓取程序，不作为实时 `CATALOG_PROVIDER` 的运行底座。

当前豆瓣公开响应没有可靠的 TMDb/IMDb 共同 ID。Core 和 Web Console 因而通过显式 `provider_id` 选择豆瓣或 TMDb，不执行标题加年份的静默自动合并；两个 Provider 的评分、详情、缓存和错误状态保持来源隔离。

`douban-watchlist` 已验证公开用户想看页的列表模式：固定使用 `sort=time&filter=all&mode=list`，并分别读取 `type=movie` 与 `type=tv` 后按加入日期归并。Manifest 只配置数字 `user_id`，不配置 Cookie；非公开页面、登录跳转、验证码或保护页必须明确失败，不能绕过。插件用不透明复合游标保存两个类型的 `start` 与页内位置，单次最多返回 30 项。

公开想看页返回 HTML。插件不得绕过宿主自行创建无限制网络客户端；`core.http.v1` 以向后兼容方式增加 `get_text`，与既有 `get_json` 共享 http/https 校验、超时和最大响应体限制。平台 DOM 解析仍完全属于外部插件仓库。

正式运行时，用户在 Sundarr `/app/plugins` 配置插件，Core 通过配置 API 把 Token 加密持久化到 `PluginConfig`。环境变量仅供上面的仓库级隔离测试使用；Core 已使用数据库外主密钥完成敏感配置静态加密。

SeedHub v2 使用单插件 `plugin_id=seedhub`，提供 `source.search.v1` 与 `source.detail.v1`。列表搜索必须保持轻量；详情跳转解析只请求经过主机、路径和查询字段白名单清洗的 SeedHub URL，并使用总量上限与有界并发。完整资源链接属于 API 业务结果，不得写入日志、fixture、断言信息或验收文档。

当前 SeedHub 实现已通过实时 Provider、Core API、详情收藏、启动恢复、`/app/plugins` 和 `/app/search` 验收。v2 运行入口使用唯一命名空间 `src.sundarr_official_sources`，旧 `sources/` 仅保留 flat v1 兼容，避免多仓库或重装时复用通用模块缓存。官方 GitHub 已发布，Core 当前从官方 URL 锁定 `a10b902`。

## 6. 生命周期与安全

- 插件只能 `require()` Manifest 明确声明的 Core 能力。
- 动态 `health_check()` 返回 `PluginHealthResult`；Core 仍执行静态合同与 provides 一致性校验。
- 候选激活失败必须释放副作用，旧 active 实例继续服务。
- 外部 Python 插件是用户信任代码，不是沙箱代码。
- 日志、诊断和异常不得输出密码、Token、Cookie 或完整私有链接。

## 7. 发布和更新

```text
正常 Git commit
  -> Sundarr fetch 候选元数据
  -> checkout 明确 commit
  -> 候选校验和健康测试
  -> 成功后原子切换 current_commit
  -> 失败时保留旧 commit 和 Activation
```

`fetch` 不等于应用更新。启动恢复只加载本地缓存中数据库锁定的 commit，不自动执行远程最新代码。
