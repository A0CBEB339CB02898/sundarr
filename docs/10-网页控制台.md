# 网页控制台

本文档定义 Sundarr MVP Web Console 的范围、页面和交互。

---

## 1. 技术选择

MVP Web Console 使用：

```text
React
Vite
FastAPI API
```

FastAPI 只作为 API 后端，不做 Jinja2 页面渲染。

---

## 2. 设计目标

Web Console 是核心控制台，并将包含媒体发现中心；它不是完整本地媒体库 UI。

目标：

```text
搜索资源
通过筛选、热门、分类和海报展示发现媒体
查看媒体详情和候选资源
选择候选资源
管理媒体源配置
管理资源和资源链接收藏
管理多个 SMB 连接
浏览 SMB 目录
管理媒体库
创建归档任务
查看任务进度
取消 / 重试任务
显示关键错误和中断提示
管理远程媒体库和同步绑定
手动触发远程媒体库同步扫描
```

---

## 3. 不做事项

MVP Web Console 不做：

```text
登录注册
多用户权限
角色管理
完整本地媒体库 UI
本地媒体库海报墙
播放器和观影进度
完整 NAS 文件管理器
拖拽式文件管理
任意 NAS 文件删除
在线编辑 Source Adapter
配置版本回滚
审计日志
```

## 4. 页面结构

MVP 页面：

```text
/app/discover         已实现的统一媒体发现模块
/app/discover/:media_subject_id  已实现的媒体详情
/app/sources           已安装媒体源列表和测试
/app/search            具体资源链接搜索和候选资源
/app/favorites         收藏资源和收藏链接
/app/transfers         完整任务列表和任务详情
/app/storage           SMB 连接列表、连接测试、目录浏览
/app/libraries         本地媒体库管理
/app/remote-libraries  远程媒体库管理
/app/status            API / Worker / DB / Redis 状态摘要
/app/plugins           插件仓库、插件实例、配置、启停和诊断
```

当前没有独立 `/app/sync` 页面；同步绑定和扫描操作由远程媒体库页面承载。Phase 10.3 已增加 `/app/plugins` 插件仓库管理入口，但不会提供 Python 代码编辑器。

媒体发现 Core 与 Web Console 已完成结构性收口，不建设面向用户的 Mock 数据链；Phase 10.3 继续使用真实数据回归页面和 Core。TMDb 主 `CATALOG_PROVIDER` 与豆瓣补充 `CATALOG_PROVIDER` 已于 2026-08-31 通过真实海报墙、搜索、筛选、详情、来源切换和启动恢复验收；豆瓣想看是待开发的独立 `WATCHLIST_PROVIDER`。数据采用核心身份与最小快照持久化、易变详情缓存的 A+ 策略。`/app/discover` 和详情路由已实现；未启用真实 Provider 时展示明确空状态。当前 `/app/search` 仍表示具体资源关键词聚合搜索。

发现页必须展示当前目录 Provider 提供的来源署名：来源名称、主页、声明和可选官方标识。署名位于发现模块的“数据来源”区域，外部标识不得压过 Sundarr 主品牌；没有 attribution 的旧 Provider 不显示占位声明。启用多个目录 Provider 时，页面提供显式“数据来源”选择，`provider_id` 写入 URL query，并用于内容流、搜索、筛选和详情请求；不自动混合缺少共同稳定外部 ID 的结果。

Web Console 页面路由使用 `/app/*` 前缀，避免与 FastAPI API 路由 `/search`、`/sources`、`/storage`、`/transfers`、`/health` 在 Vite dev proxy 下冲突。

## 4.1 开发顺序

Web Console 按可验证停止点推进：

```text
Phase 7.1 Web Console Shell
Phase 7.2 Status Page
Phase 7.3 Transfers Page
Phase 7.4 Storage Page
Phase 7.5 Search Page
Phase 7.6 Sources Page
Phase 7.7 Web Console Polish And Closure
Phase 7.8 Web Console UI Polish
```

顺序理由：

```text
先 Shell，统一导航、API client 和错误展示。
再 Status，用最小 API 调用验证前后端闭环。
再 Transfers，优先把 Phase 6 cancel / retry / logs 暴露给用户。
再 Storage，让用户能配置 SMB 并看到 STORAGE_CONFIG_CHANGED 影响。
再 Search，形成聚合搜索和结果展示的最小前端流程。
最后 Sources 和统一收口，避免过早扩大到供应商开发。
```

Phase 7 期间仍不启动真实供应商开发或真实集成测试；这些工作等 Web Console 具备任务操作界面后再做。

## 5. Resource Search 页面

状态：当前已实现的具体资源关键词聚合搜索基线；保持独立，不并入媒体目录发现。

功能：

```text
输入 keyword
选择结果类型：全部 / 磁力 / 夸克网盘 / 阿里网盘 / 百度网盘 / 迅雷网盘
展示聚合搜索结果
展示 source、quality、links、score、链接有效性
点击结果链接打开原链接
每条链接提供操作区：保存到网盘、复制链接
```

交互规则：

```text
搜索调用 GET /search。
搜索结果按真实链接去重。
搜索返回前同步执行链接有效性检测，检测失败不阻塞结果展示。
当前搜索页不创建 Transfer。
保存到网盘是后续模块入口，当前只保留操作位置。
```

### 5.1 统一媒体发现中心

已确认的产品范围：

```text
带筛选条件的媒体搜索
热门资源
分类资源
发现型海报墙
媒体详情
关注列表入口
从媒体条目继续查找候选资源
```

边界：

```text
不展示本地媒体库海报墙。
不提供播放和观影进度。
不承担完整本地媒体管理。
已纳入当前 MVP 并完成通用 Core 与页面；TMDb 是已验收的真实主目录、豆瓣目录是已验收的可选补充，豆瓣想看是下一项独立列表接入。
媒体身份已确认使用内部 UUID，并可绑定多个外部平台 ID。
统一入口为 /app/discover，详情为 /app/discover/:media_subject_id。
/app/search 只搜索具体资源链接；媒体详情可以进入资源搜索，但具体关联参数尚待确认。
顶部一级导航固定平铺“热门 / 电影 / 剧集 / 动漫 / 综艺”，热门位于第一位；搜索框位于导航右侧并保持独立提交。
热门入口显示热门电影、热门剧集、分类推荐和关注更新分区；电影、剧集、动漫和综艺切换为对应统一海报网格。
关键词、一级入口和筛选条件写入 URL query，刷新、前进后退和直接访问 URL 时恢复状态；旧 URL 继续兼容。
各内容流分区独立处理 loading / empty / error，不因单区失败清空整页。
题材、地区、年份和排序均使用平铺标签，不使用下拉框；题材支持简单多选，地区保持单选。
年份默认展示“全部 / 近三年 / 2020年代 / 2010年代 / 2000年代 / 90年代 / 80年代 / 更早”，精确年份按需展开。
筛选区顶部显示可单独移除的当前条件，并提供一键清除；筛选标签变更后直接更新结果，不要求额外填写或确认表单。
基础排序展示“热门 / 评分最高 / 最新发布 / 最新上映 / 收藏最多 / 观看最多”，但只允许当前公共合同和 Provider 支持的项交互。当前可用映射为热门、评分最高和最新上映；其余选项明确标记暂不支持，不得伪造排序结果。
IMDb 评分、评分人数、资源质量、语言和字幕类型放入默认收起的“更多筛选”，同样按能力启用。Provider 来源是顶层数据源选择，不属于内容筛选条件，并使用平铺选择而不是下拉框。
搜索提示覆盖片名、演员、导演和关键词，但页面必须说明实际检索范围由当前目录 Provider 决定；Core 不能把不支持的人物搜索伪装为已支持。
数据来源选择写入 provider_id query；刷新、前进后退、复制 URL 和进入详情时保持当前来源。
豆瓣与 TMDb 缺少共同稳定外部 ID 时不自动混合、去重或覆盖评分；用户切换来源查看各自结果。
目录插件和想看插件在管理界面独立显示启用状态、测试结果和最后错误。
同一仓库由 Manifest v2 声明的多个插件按 plugin_id 分开展示和配置；仓库 commit 状态与插件 Activation 状态不得合并成一个模糊开关。
搜索、筛选、热门和分类使用“加载更多”，Provider 分页只通过 Core continuation token 访问。按钮位于当前海报网格下方；加载时保留已有卡片并禁用重复提交，失败通过现有错误反馈提示且允许重试。后续页按 media_subject_id 去重追加，token 不写入 URL；刷新、切换 Provider 或改变筛选后从首屏重新开始。关注更新当前没有 continuation token，不显示伪分页入口。
缓存或 Provider 故障时，已有媒体卡片至少展示规范标题、年份和最后可用海报；降级状态不得伪装成完整实时数据。
列表缺失年份时先展示“正在补全年份”，Web Console 按 Provider 分组并以最多 6 条为一批调用 Core；成功后原位更新为真实年份，仍无法获得时展示“年份待补充”。补全不阻塞海报墙首屏，不因单条失败清空分区。
海报优先使用 Provider 返回的 HTTPS 地址直接加载；浏览器因防盗链、ORB 或跨源策略触发图片错误时，自动切换到 `/discover/{media_subject_id}/poster` 同源中继。该降级对用户透明，第二次失败才展示“暂无海报”，不能造成整张卡片或分区错误。
不同平台评分必须显示来源，不展示无来源的合并评分。
```

## 6. Transfers 页面

功能：

```text
查看任务列表
查看任务详情
查看任务状态
查看 done_bytes / total_bytes / speed / ETA
查看当前文件
取消任务
重试任务
查看错误码和错误信息
```

任务展示分为两层：

```text
全局右侧浮动任务面板：展示当前所有任务的状态摘要，便于在任意页面查看进度。
/app/transfers 页面：保留为完整任务列表、任务详情、日志、取消和重试操作页面。
```

右侧浮动任务面板规则：

```text
默认显示最近活跃任务和运行中任务。
支持展开查看更多任务。
支持跳转到 /app/transfers 查看详情。
在移动端应降级为底部抽屉或可折叠入口，避免遮挡主要内容。
```

必须突出显示：

```text
STORAGE_CONFIG_CHANGED
VERIFY_FAILED
CLOUD_CLEANUP_FAILED
NAS_WRITE_FAILED
```

`STORAGE_CONFIG_CHANGED` 提示文案必须说明：

```text
SMB 配置已变更，任务已中断。
.downloading 文件和 cloud staging 已保留。
可在确认新配置后重试。
```

## 7. Storage 页面

功能：

```text
查看 SMB 连接列表

编辑 host / port / share / username / password / domain / base_path
测试 SMB 连接
```

规则：

```text

password 不回显明文。

目录浏览只能在允许范围内进行。
SMB 连接测试必须由后端执行，验证后端运行环境到 SMB 服务器的网络、DNS、认证和权限。
```

API：

```text
GET  /storage/smb-connections
POST /storage/smb-connections/create
POST /storage/smb-connections/{connection_id}/update
POST /storage/smb-connections/{connection_id}/test
GET  /storage/smb-connections/{connection_id}/browse
```

## 8. Sources 页面

功能：

```text
查看 source 列表
查看已安装搜索源
测试 source 搜索
```

限制：

```text
不允许在线编辑 Source Adapter。
不允许上传执行代码。
不在配置或数据库中保存可执行 Python 代码。
不支持通过 Web Console 配置复杂网站爬虫。
不要求用户维护本地文档/表格作为主要媒体源。
不允许通过 Web Console 创建或编辑搜索源代码；搜索源由 Source Adapter 代码定义。Web Console 可以管理已安装 Adapter 的启用、禁用、参数和测试。
```

说明：当前 Sources 页面是已安装搜索源的列表和测试入口。插件仓库管理已使用独立 `/app/plugins`，两者不再混用。

插件管理页规则：

```text
仓库列表管理可信 Git 地址、分支、锁定 commit、更新、回滚和仓库级错误。

配置表单由 Manifest config_schema 生成；password/secret 字段使用密码输入框，不回显原值。
已保存敏感值显示“已配置”；提交 *** 表示保留，替换和清空必须显式操作。
正式 Token 通过 Core 配置 API 写入 PluginConfig，不要求用户修改 API / Worker 环境变量。
页面不得上传、展示或编辑 Python 代码。
```

### 8.1 配置缺口引导

Web Console 启动后调用 `GET /configuration/readiness`。存在缺口时，在主内容顶部展示可展开的内联引导条：

```text
显示当前缺口数量和最优先的下一步，不用模态框阻断其他操作。
每项提供明确动作并跳转到对应配置页面。
用户可以关闭本次提示，或选择“下次不再询问”。
“下次不再询问”把当前 fingerprint 写入 localStorage；数据库不保存浏览器偏好。
同一 fingerprint 后续不再自动展示；缺口集合变化后允许重新提示。
API 失败时静默保留主界面可用，不把配置提示失败升级为全局故障。
```

页面规则：

```text
不展示启用 / 禁用状态。
不展示 legal_note、last_error_code、last_error_message 等历史数据库字段。
列表只展示搜索源名称、原网址、说明摘要和详情入口。
详情弹窗展示 ID、原网址、说明，并在弹窗内提供测试搜索表单。
测试搜索支持 keyword、result_type、limit。
测试结果展示 Adapter 内部请求、解析、提取、预览等步骤日志和 RawSearchItem 预览。
```

API：

```text
GET  /sources
GET  /sources/{source_id}
POST /sources/{source_id}/test
```

Search 页面规则：

```text
搜索表单只保留关键词和结果类型。
搜索结果默认展示全局去重结果。
结果区提供横向 tab：全部 + 每个 source 的独立结果。
点击结果主体打开链接；链接操作区提供保存到网盘和复制链接。
```

## 10. 媒体库同步页面边界

远程媒体库、同步绑定、扫描和任务创建统一由 `/app/remote-libraries` 承载，不再保留旧下载页面或新增独立 `/app/sync` 页面。

限制：

```text
不在 Web Console 中挂载网盘。

页面默认展示列表，不默认展开空新增表单。
远程媒体库和同步绑定只选择已配置对象，不重复填写 SMB 凭据。
删除源文件和空目录必须只发生在下载成功并完成校验之后。
```

## 11. 前端状态策略

MVP 不引入复杂全局状态方案，除非实现阶段确认需要。

推荐：

```text
React local state
fetch API wrapper
simple polling for transfer progress
```

```text
MVP 使用轮询。
后续可改 WebSocket 或 SSE。
```

## 12. 主题和响应式

Web Console 需要支持：

```text
亮色模式
暗色模式
跟随系统
```

主题规则：

```text
默认跟随系统。
用户可在 Web Console 中切换主题。
MVP 无多用户系统，主题偏好优先保存在浏览器本地。
```

响应式规则：

```text
桌面端优先保证多列布局和右侧任务面板可用。
移动端必须可读、可操作，不出现输入框和按钮错位。
移动端任务面板应使用底部抽屉或折叠入口。
表单控件、按钮和提示文案需要统一对齐和间距。
```

## 13. 验收标准

Web Console 完成时必须满足：

```text
可以搜索资源。
可以创建 transfer task。
可以查看任务进度。
可以取消和重试任务。
可以查看和修改多个 SMB 连接。
可以测试 SMB 连接。
可以浏览 SMB 目标目录。
可以查看已安装搜索源，并在详情弹窗中测试搜索流程。
可以管理远程媒体库和同步绑定。
可以通过全局任务面板查看当前任务状态摘要。
可以在 /app/transfers 查看完整任务列表和详情。
支持亮色、暗色和跟随系统三种主题模式。
桌面端和移动端布局均可用。
SMB 配置变更导致任务中断时有明确提示。
取消、重试、保存 SMB 配置、创建任务、启用或禁用 source 等关键操作需要用户确认。
不提供登录注册和权限管理。
不提供完整本地媒体库 UI。
```
