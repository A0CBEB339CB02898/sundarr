# 测试与验收

本文档定义 Sundarr MVP 必须覆盖的测试范围。

---

## 1. 测试原则

MVP 自动化测试不得依赖：

```text
真实网盘
真实 NAS
真实 SMB 服务器
真实外部资源站
```

必须提供：

```text
Mock/Local Provider
LocalWriter
可替换 StorageWriter
可控 Source fixture
```

每完成一项非文档型开发任务后，必须运行对应回归测试和冒烟测试。

最低回归规则：

```text
后端代码变更必须运行 pytest。
前端代码变更必须运行 npm run build，必要时运行前端测试。
配置或 Docker 变更必须运行相关启动或配置校验。
失败测试必须优先修复，不能继续积累新功能。
```

最低冒烟规则：

```text
后端 API 变更必须对本次改动的 endpoint 做最小调用，确认状态码和关键响应字段可用。
后端 CLI 或 Worker 变更必须运行对应命令或等价入口，确认进程、状态或任务流转可触发。
前端页面变更必须确认受影响路由可打开，关键交互可触发，且不会出现空白页或运行时错误。
配置、启动或 Docker 变更必须确认应用可启动，并通过 /health、配置读取或连接测试完成最小验证。
```

冒烟测试用于验证本次交付入口真实可用，不替代回归测试。冒烟测试可以通过自动化测试、TestClient/API 调用、CLI 命令、启动后访问 `/health`、前端页面本地打开检查，或与本次交付等价的最小端到端验证完成。

如果某项回归测试或冒烟测试因环境限制无法运行，必须在交付说明中明确说明原因和风险。

默认 pytest 使用 SQLite 内存数据库验证模型、服务和 API 行为，不要求本机 PostgreSQL 已启动。真实 PostgreSQL 连通性属于本地集成环境检查，必须通过 `/health` 或独立启动校验确认。

Windows 本地运行 pytest 时，默认使用项目内 `.sundarr` 目录作为 pytest 临时目录和 cache 目录，避免系统 Temp、pytest 内置 basetemp 或默认 `.pytest_cache` 权限、占用问题影响测试结果。推荐命令：

```bash
.venv\Scripts\python -m pytest
```

不要在 Windows / Codex 沙盒环境下手动传入 `--basetemp`。项目测试通过 `tests/conftest.py` 接管 `tmp_path` 到 `.sundarr\pytest-tmp`，并通过 `pyproject.toml` 固定 cache 到 `.sundarr\pytest-cache`，避免 pytest 内置临时目录在混合权限运行后生成仅管理员或系统可访问的私有 ACL。

真实 SMB 可用于手动开发测试，以减少过度 mock 带来的偏差。但这类测试必须满足：

```text
不纳入默认 pytest。
不得要求 CI 或其他开发者具备真实 NAS。
不得提交真实 SMB 密码、host 私密信息或可访问路径。
测试目标目录应使用专用目录，例如 /SundarrManualTest。
真实写入测试必须只操作测试目录，避免误删媒体库正式文件。
```

真实媒体源测试原则：

```text
每个真实网站 Adapter 必须有 fixture 测试。
默认自动化测试不依赖实时外部网站。
实时网站访问作为手动集成验收或显式集成测试，不纳入默认 pytest。
不建设面向用户或阶段演示的 MockCatalogProvider 数据链；Core 单元与契约测试可使用离线测试替身和固定 fixture 覆盖搜索、筛选、热门、分类、详情和海报字段。
默认 pytest 不调用 TMDb、豆瓣或其他实时目录服务。
每个真实插件新增或修改后必须执行显式实时集成测试，使用真实响应回归 Provider 合同、Core 规范化、缓存降级、API 和受影响的 Web Console 主路径。
首个 TMDb 插件已于 2026-08-31 完成搜索、热门、分类、详情、分页、降级和海报墙端到端真实数据验收，Plugin API v2 已据此冻结。后续真实插件仍必须重复执行其对应的实时集成、Core API、Web Console、脱敏和失败隔离验收。
同一仓库中的 douban-catalog 与 douban-watchlist 必须分别测试启用、禁用、失败和配置错误。
同仓库任一必须启用声明候选失败时 current_commit 不切换，旧 Activation 保持可用。
豆瓣补充失败时 TMDb 主目录仍可返回；想看同步失败时不得影响目录查询。
douban-catalog 的实时验收至少覆盖关键词搜索、电影/剧集热门、题材分类、电影/剧集详情、分页、海报地址和来源署名。
豆瓣海报验收必须在真实浏览器中确认：外链因防盗链或 ORB 失败后自动使用 Core 同源中继，列表和详情图片具有非零 naturalWidth；TMDb 等可直连图片不应被强制改走中继。
海报中继自动化测试必须覆盖持久化 URL 寻址、Provider 快照来源匹配、image_referer_url、HTTPS/MIME/大小限制、拒绝任意 URL 参数、拒绝本机或内网字面 IP、拒绝重定向和上游失败不泄露响应正文。
直连与中继同时失败时单卡片展示“暂无海报”，不得使所在分区或详情页整体报错。
豆瓣实时测试使用无需账号的公开目录响应，不把实时响应原样固化为 fixture；fixture 只保留经过审查的最小字段和异常样本。
发现页同时启用 TMDb 与豆瓣时，可以显式选择 Provider；provider_id 在刷新、前进后退和详情跳转后保持一致，切换来源不会把不同平台评分静默覆盖。
禁用或故意破坏 douban-catalog 后，显式选择 TMDb 的 Core API 和发现页仍可用。
WATCHLIST_PROVIDER 测试使用固定 fixture 和 Core 持久游标，不启动插件自有永久轮询。
豆瓣想看离线测试覆盖 movie / tv 双流按 added_at 归并、`data-cid` 幂等键、列表页不足 30 项、页内游标、跨页续拉、失效条目和重复 pull 不丢不重。
豆瓣想看显式实时测试使用用户明确提供的公开 user_id，至少连续拉取两页并验证媒体类型、subject ID、加入日期和游标推进；不得把真实页面、用户完整列表或 Cookie 保存为 fixture。
Core 真实验收覆盖首次同步入库、相同 cursor 重试幂等、继续同步不重复、API / Worker 重启恢复、与 douban-catalog 独立启停以及错误/日志不泄露用户页面内容。
secret/password 配置落库后不是可读明文，API 仅返回 `***`；API 与 Worker 使用同一数据库外密钥可以恢复配置。
`/configuration/readiness` 不返回敏感值，缺口集合变化会改变 fingerprint。
Redis 清空后 MediaSubject、外部 ID、最小展示快照和用户状态仍存在。
目录缓存覆盖命中、未命中、过期和 Provider 超时路径。
Provider 失败时返回最小展示快照并标记降级，不以 null 覆盖已知字段。
没有缓存或快照时返回明确错误，不伪造目录详情。
TMDb 与豆瓣评分保持独立来源和抓取时间。
无搜索条件时 /app/discover 显示分区内容流。
提交关键词或筛选后切换为统一海报网格。
搜索、筛选、热门和分类返回 continuation_token 时显示“加载更多”；点击后追加且按 media_subject_id 去重，按钮加载中禁用，失败保留已有条目并允许重试。
切换 Provider、修改筛选、刷新或浏览器前进后退后清除旧 continuation token，从新条件首屏开始；token 不进入 URL。
缺失年份的可见条目按 Provider 分组、每批不超过 6 个渐进补全；单条详情失败不阻断同批或页面，成功年份写入 PostgreSQL 并立即更新卡片。
年份补全 API 必须覆盖已有年份不访问 Provider、搜索结果按外部 ID 精确补全、搜索不匹配时回退详情、缺失年份写回、批内失败隔离、Provider 不可用、超过 12 个 ID 拒绝和缓存页合并数据库最新快照。实时豆瓣验收必须包含热门或分类续页，确认补全不会依赖移动端详情接口的连续成功。
刷新、浏览器前进后退和直接打开 URL 时恢复相同搜索状态。
热门电影、热门剧集、分类推荐或关注更新单区失败时，其余分区仍可用。
URL query 不包含目录 Provider 凭据或其他敏感配置。
一级导航覆盖热门、电影、剧集、动漫和综艺；动漫/综艺缺少 Provider 题材映射时显示明确不支持状态。
基础筛选覆盖题材多选、地区单选、年代/精确年份和三种已支持排序。
非法媒体类型、年份倒置和未知排序返回明确参数错误。
未启用 IMDb 评分、评分人数、资源质量、语言和字幕类型等高级筛选时，页面只能显示明确的不可用状态，不得发送伪请求。
插件不支持某筛选时不得静默忽略并宣称筛选成功。
多个 genre 必须全部进入 Core 列表查询模型并使用 AND 语义；Provider 不得只取第一个。
region 控件保持单选，重复传入两个及以上 region 时返回 422，不静默截断。
一级入口、重复 genre、region、年份和 sort 均可从 URL 恢复；既有不含 category 的 URL 继续兼容。
```
