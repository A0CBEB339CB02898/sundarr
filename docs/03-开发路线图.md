# 开发路线图

本文档是 Sundarr 阶段状态和执行顺序的唯一事实源。只保留当前结论与验收门；已完成阶段的逐次实施过程通过 Git 历史追溯。

更新时间：2026-08-31。

## 1. 总体原则

- 先保证核心同步链路可启动、可追踪、可恢复，再扩展真实平台。
- Core 保留稳定业务合同和运行时；平台实现放在外部官方仓库。
- 默认自动化测试离线可重复，真实插件另做显式实时集成验收。
- 真实数据暴露出的通用合同问题可以回修 Core，但不得为单一平台增加专用分支。
- 每个阶段必须有可停止、可独立验收的交付面。

## 3. 当前阶段：Phase 10.3

### 3.1 已具备前提

- `SOURCE`、`CATALOG_PROVIDER`、`WATCHLIST_PROVIDER` 三类公共合同和 Runtime Registry 已实现。
- Manifest v2 多插件加载、仓库级候选验证、原子切换、失败回滚和 API/Worker 启动恢复已实现。
- 媒体发现 Core 已提供身份归一化、最小快照、缓存降级、搜索、热门、分类、详情和想看游标。
- `sundarr-plugin` 已完成首个 `tmdb-catalog` 的 Manifest v2、平台映射、离线 fixture、公共合同测试、实时测试和 Core API / Web Console 真实数据验收；`sundarr-sources` 保留 SOURCE-only 发布边界。
- Core 已根据 TMDb 电影/剧集同号风险修正详情合同：详情调用和缓存键均保留 `media_type`。

TMDb 主目录的首个真实纵向切片已经通过生产级功能验收；这不等于豆瓣、SeedHub 或真实 SMB 发布门已经通过。

### 3.2 交付顺序

1. **TMDb `CATALOG_PROVIDER`（P0）**
   - 已在 `sundarr-plugin` 增加真实 v2 Manifest、配置 schema、入口和平台映射。
   - 已离线覆盖搜索、热门、分类、详情、分页、异常响应及 Core API 集成。
   - 已完成 `/app/plugins` 仓库与插件配置页面，运行时 Token 通过 Core 配置 API 持久化。
   - 已完成 `PluginConfig` 敏感字段静态加密；本地使用受限密钥文件，部署可从数据库外注入主密钥。
   - 已完成统一配置就绪 API 和 Web Console 非阻断引导；同一缺口集合允许在当前浏览器选择不再提醒。
   - 本地 CLI 启动完成时已明确打印可访问的 Web Console 地址。
   - 已使用真实 TMDb 数据回归 Core API 与 `/app/discover` 海报墙。
   - 已修正真实数据暴露的合同问题，并于 2026-08-31 冻结 Plugin API v2。
2. **SeedHub `SOURCE`（P1）**
   - 保留在 `sundarr-sources`。
   - 将现有 flat v1 聚合入口迁移为 `plugin_id=seedhub` 的 Manifest v2，声明 `source.search.v1` 与 `source.detail.v1`。
   - 列表搜索只返回标题、详情 URL 和 `has_more_links=true`，不得预抓全部详情。
   - 按需详情只接受 SeedHub 官方主机的 `/movies/{id}/`；解析内部 `/link_start/` 时删除 `movie_title` 等非必要参数，只保留 `seed_id` 或 `redirect_to`。
   - 跳转解析必须使用可配置的总量上限和有界并发，单条失败只跳过该链接，不能拖垮整个详情请求。
   - 验证真实轻量搜索、按需详情、链接解析、Core 收藏标记、`/app/plugins` 诊断和 `/app/search` 页面。
3. **豆瓣目录 `CATALOG_PROVIDER`（P2）**
   - 作为 TMDb 可选补充，失败不得阻断主目录。
   - 保留来源字段，不能用无来源评分覆盖 TMDb 数据。
4. **豆瓣想看 `WATCHLIST_PROVIDER`（P3）**
   - 与豆瓣目录独立配置、启停、健康检查和报错。
   - Core 管理调度、游标、重试和持久状态；插件只响应一次拉取。

### 3.3 每个真实插件的验收门

- 配置 schema、离线 fixture、合同测试、健康检查齐全。
- 默认 `pytest` 不依赖实时网站或凭据。
- 显式实时集成测试使用真实数据并通过。
- 正式运行凭据通过 Web Console / Core 配置 API 写入数据库；只有隔离实时测试使用测试进程环境变量。
- 对应 Core Provider 合同、API 主路径和受影响 Web Console 页面回归通过。
- 凭据、Cookie、Token、完整私有链接不进入提交、日志或错误响应。
- 加载失败不影响 Core `/health`，候选失败保留旧 Activation。

### 3.4 Phase 10.3 初步验收点

TMDb 垂直切片已于 2026-08-31 完成第一次真实插件验收：

- 真实搜索、热门电影、热门剧集、题材/地区/年份筛选和详情可用。
- 海报 URL、外部 ID、媒体类型、标题和年份映射正确。
- `tmdb.movie` 与 `tmdb.tv` 身份命名空间不会发生同号碰撞。
- Provider 故障时返回缓存或最小快照，并明确标记降级。
- Plugin API v2 的修改已经通过离线全量回归和真实数据回归。
- 插件仓库、启停、配置和脱敏错误可以在 `/app/plugins` 管理；敏感配置不会明文落库。

本次验收记录：插件仓库实时测试 `2 passed`，插件默认离线测试 `17 passed / 2 deselected`，Core `265 passed`，Web 生产构建通过；真实搜索、电影/剧集热门、题材/地区/年份分类、详情、分页续页、海报加载和 Provider 禁用后的最小快照降级均通过。冻结基线为 Core `3ce9c8e` 与官方插件仓库 `f83f43d`；后续破坏性合同变更必须提升协议版本。

### 3.5 SeedHub v2 验收点

- Core 从锁定的 `sundarr-sources` commit 激活单个 `seedhub` v2 SOURCE，运行能力与 Manifest 一致。
- 真实列表搜索在 Core 的 10 秒单源截止时间内返回候选，`source_results.error` 为空。
- 真实按需详情返回至少一个 Core 可识别链接；完整 URL 只出现在正常 API 业务响应，不进入日志、测试快照或提交。
- 非 SeedHub 主机、非 `/movies/{id}/` 详情地址被明确拒绝，避免把详情接口变成通用 SSRF 入口。
- `/search`、`/search/detail`、资源和资源链接收藏标记、Sources 测试入口及 `/app/search` 浏览器链路通过。
- 默认离线测试、显式实时测试、Core 全量测试和 Web 生产构建全部通过；候选失败不影响 `/health` 和已激活的 TMDb。

## 4. MVP 发布前并行验收

Phase 10.3 不替代真实 SMB 发布门。发布前必须在用户明确提供的测试目录中验证：

- 远程 SMB 媒体库扫描并创建任务。
- 目标 SMB 写入 `.downloading`、续传、校验和原子重命名。
- 成功后按配置删除来源文件与空目录。
- 中断、重试、取消、配置变化和 Worker 重启可恢复。
- 测试目标被严格限制在授权目录，不误删其他文件。

## 5. 后续阶段

### Phase 11：人工智能工具接口

在 Phase 10.3 和发布门稳定后，提供媒体发现、资源搜索、收藏和任务查询的稳定工具接口。Cordis / DeepSeek Harness 如需接入，只能作为调用公开 HTTP API 的外部桥接，不能直接访问数据库、SMB 或 Worker 内部对象。

### 非近期主线

- `TRANSFER_DRIVER` 与 `NOTIFICATION` 仅保留扩展方向。
- qBittorrent、BT/磁力、真实网盘直链、Aria2、Alist 和 rclone 不进入 MVP。
- 不实现登录、多用户权限、播放器、观影进度或完整本地媒体库管理界面。
