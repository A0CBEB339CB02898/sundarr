# 开发路线图

本文档是 Sundarr 阶段状态和执行顺序的唯一事实源。只保留当前结论与验收门；已完成阶段的逐次实施过程通过 Git 历史追溯。

更新时间：2026-09-21。

## 1. 总体原则

- 先保证核心同步链路可启动、可追踪、可恢复，再扩展真实平台。
- Core 保留稳定业务合同和运行时；平台实现放在外部官方仓库。
- 默认自动化测试离线可重复，真实插件另做显式实时集成验收。
- 真实数据暴露出的通用合同问题可以回修 Core，但不得为单一平台增加专用分支。
- 每个阶段必须有可停止、可独立验收的交付面。

## 3. Phase 10.4：已完成

2026-09-04 代码审计确认：现有离线测试和前端构建通过，但这不能替代 PostgreSQL、容器进程边界和多 Worker 语义验证。Phase 10.3 的真实插件功能结论继续有效；Phase 10.4 不扩展产品功能，优先修复以下发布阻断项：

1. Docker 默认不向宿主网络发布 PostgreSQL、Redis 和无认证 API，只暴露本机 Web 入口；API 与 Worker 必须共享同一个数据库外插件加密主密钥。Compose 静态配置继续维护，但真实 Compose 启动不再作为 Phase 10.4 停止条件。
2. Alembic、ORM 与实际 PostgreSQL schema 恢复一致，重点修正 `sync_seen_files.binding_id` 的外键语义；新增真实 PostgreSQL 迁移与行为测试。
3. SMB 同步任务显式重试必须重新解析当前绑定与连接配置，来源文件在同一路径发生版本变化后必须能创建新任务。
4. `pending` 任务和稳定扫描记录使用数据库原子认领；`worker.concurrency` 必须代表真实并发而不是领取批大小。
5. 进度写库节流、来源清理失败的独立重试、SMB 凭据静态加密已完成；已建立 Python 最低静态检查门并修复前端高危依赖。5634 行全局样式已按基础、组件和页面域拆为八个保持原级联顺序的模块；大型 React 页面与后端编排文件继续按独立交付拆分，避免与状态机修复混为一次高风险变更。

Phase 10.4 初步验收门：

- Core 全量离线测试和 Web 生产构建通过。
- Compose 静态配置可以解析，API / Worker 共享持久运行目录，基础设施端口默认不暴露；本阶段不要求当前开发机完成真实 Compose 启动。
- 全新 PostgreSQL 可以从空库升级到唯一 head，历史 schema 升级不丢失无法映射的数据。
- SQLite 快速测试之外，至少覆盖一次真实 PostgreSQL 外键、原子认领和迁移检查。
- SMB 重试、配置变化、同路径文件替换和清理失败均有回归测试。

截至 2026-09-07，以上代码侧验收已经通过：Core 全量离线回归、Web 生产构建、依赖安全审计、全新 PostgreSQL 迁移/外键/双事务认领和 Alembic 漂移检查均通过。当前机器未安装 Docker，因此这里只完成 Compose YAML 与服务依赖结构校验；真实容器启动和真实 SMB 授权目录验收仍是停止条件。全局样式拆分已经完成；大型 React 页面和后端编排文件继续作为独立交付，不与本次状态机及数据迁移提交混合。

## 5. MVP 发布前并行验收

Phase 10.3 不替代真实 SMB 发布门。发布前必须在用户明确提供的测试目录中验证：

- 远程 SMB 媒体库扫描并创建任务。
- 目标 SMB 写入 `.downloading`、续传、校验和原子重命名。
- 成功后按配置删除来源文件与空目录。
- 中断、重试、取消、配置变化和 Worker 重启可恢复。
- 测试目标被严格限制在授权目录，不误删其他文件。

## 6. 当前与后续阶段

### Phase 10.5：MVP 可用性与发布闭环

本阶段不增加新的顶层插件类型，不进入 AI Tool API，也不引入 BT、网盘直链或完整媒体管理。按优先级完成：

1. **10.5.1 配置诚实性（已完成）**：就绪检查区分阻断项与非阻断提醒；只有不存在任何可执行同步链路时才返回 `ready=false`，单个未绑定或未使用配置不得错误阻断其他有效链路。真实运行库已验证有效 movie/series 链路保持 ready，未绑定远程库和失败的未使用连接以 recommended 提醒展示。
2. **10.5.2 插件运维语义（已完成）**：检查更新只 fetch 并比较远端 commit，Web Console 仅在发现新版本后显示显式“应用更新”；应用时继续执行候选健康检查与仓库级原子切换。`auto_update` 已退出公共 API 和界面，仅保留数据库兼容列；插件详情已提供当前 Activation 诊断和手动健康检查。两个正式仓库的真实检查均确认未改变锁定 commit，四个已激活正式插件健康检查通过。
3. **10.5.3 真实主链路发布门**：在用户授权目录中完成扫描、建任务、SMB 写入、校验、原子重命名、来源清理，以及中断、重试、取消和 Worker 重启恢复。

停止条件：真实 SMB 发布门通过；就绪状态与实际可执行链路一致；插件更新不存在误导性按钮或空实现字段；默认离线回归、前端构建和受影响入口冒烟通过。

### Phase 10.6：获取意图与保存到网盘

按以下独立验收单元实施：

1. **10.6.1 获取意图模型**：新增 `AcquisitionRequest`，保存用户确认的资源链接、执行模式、目标、状态、幂等键和可脱敏错误；不把搜索结果自动变成任务。
2. **10.6.2 保存合同与宿主**：增加 `CLOUD_SAVE_PROVIDER` 的 Manifest 类型、运行合同、Registry、Activation、配置、诊断和离线 conformance fixture。
3. **10.6.3 Core 编排与页面入口**：从资源链接创建保存请求，显式选择 Provider 和目标目录，支持查询、取消或安全重试；手动保存继续可用。
4. **10.6.4 首个真实 Provider**：在 `sundarr-plugin` 交付一个真实网盘保存插件；具体平台在实施前依据公开接口、账号条件和稳定性确定，不在 Core 写平台分支。
5. **10.6.5 真实纵向验收**：资源链接一键保存成功后可被已配置远程媒体库发现；重复点击不产生不可控重复任务，凭据和完整私有链接不进入日志。

### Phase 10.7：统一传输驱动与 SMB 适配

1. **10.7.1 冻结合同**：定义 `TRANSFER_DRIVER` 的来源描述、目标媒体库、prepare/start/poll/cancel/cleanup、进度、校验和可恢复错误。
2. **10.7.2 持久选择**：TransferTask 持久化 `driver_id`、驱动版本和规范化来源；重试默认使用原驱动，禁止运行中静默改路由。
3. **10.7.3 内置 SMB 适配**：把现有 SmbWriter 包装为内置驱动，不改变扫描、`.downloading`、校验、原子重命名和清理语义。
4. **10.7.4 等价回归**：现有 SMB 自动化与真实发布门全部保持通过，驱动切换失败可回滚且不破坏已有任务。

### Phase 10.8：网盘直链下载

1. **10.8.1 来源解析**：通过受支持平台的公开接口定位文件并获取有时效的下载流或地址，认证连接器与传输合同分离。
2. **10.8.2 流式传输**：直接写入目标本地媒体库，支持临时文件、续传、限流、校验、地址过期刷新、取消和清理。
3. **10.8.3 产品入口**：资源链接可选择“直接下载”，页面展示真实进度和可恢复错误，不经过远程媒体库或额外本地暂存目录。
4. **10.8.4 真实验收**：至少一个合法可维护的平台端到端通过；不绕过会员、验证码、风控或平台限制。

### Phase 10.9：qBittorrent 下载

1. **10.9.1 驱动与配置**：在外部插件仓库实现 qBittorrent 驱动，配置由 Core 加密保存并可独立测试、启停和诊断。
2. **10.9.2 路径安全**：任务直接落到目标媒体库所在文件系统，下载中内容不可被媒体库误识别，不要求额外大容量暂存目录。
3. **10.9.3 生命周期映射**：规范化磁力/种子输入，映射添加、轮询、暂停、取消、失败、校验和完成状态，重启后可继续追踪。
4. **10.9.4 真实验收**：使用用户明确授权且合法的测试内容完成端到端回归，不提供内容分发、绕过限制或站点抓取能力。

### Phase 11：人工智能工具接口

当前已延后。完成 Phase 10.6—10.9 后再重新评估；若启动，则提供媒体发现、资源搜索、收藏和任务查询的稳定工具接口。Cordis / DeepSeek Harness 如需接入，只能作为调用公开 HTTP API 的外部桥接，不能直接访问数据库、SMB 或 Worker 内部对象。
